# 🧠 MULTI-AGENT PLANNER WITH WIMSE SECURITY & OBSERVABILITY

Production-ready мультиагентная система планирования с WIMSE-безопасностью.

---

## 📋 Описание

Мультиагентная система планирования на базе **LangGraph** и **YandexGPT** с полной наблюдаемостью, системой управления промптами через базу данных и встроенной WIMSE-безопасностью. Поддерживает автоматическую обработку входящих email.

---

## 🚀 Ключевые возможности

- **Мультиагентная архитектура** на базе LangGraph (`Research` → `Analysis` → `Execution`)
- **Интеграция с YandexGPT** через REST API
- **Полная наблюдаемость с Langfuse** (трейсинг, метрики, логи)
- **Управление промптами через SQLite** (версионирование, переключение на лету)
- **CLI-интерфейс** для управления промптами
- **Автоматическая генерация** PDF-отчетов
- **Сбор метрик** (токены, задержки, стоимость)
- **Политики безопасности** (принцип наименьших привилегий)
- **Аттестация агентов через WIMSE** (4 фазы)
- **Полный аудит** всех действий
- **Email-интеграция** (чтение и отправка писем через Яндекс.Почту)
- **Human-in-the-Loop** для критических действий

---

## 🔐 WIMSE-безопасность (4 фазы)

Проект полностью соответствует принципам **Workload Identity in Multi-System Environments (WIMSE)** согласно черновикам IETF.

### ФАЗА 1: ИДЕНТИЧНОСТЬ АГЕНТОВ (WIT)
- Каждый агент получает уникальный *Workload Identity Token (WIT)*.
- Токены подписываются и верифицируются криптографически.
- Аттестация агентов: проверка целостности и окружения.
- Peer-to-peer верификация между агентами.
- *Реализовано в:* `config/identity.py`, `agents/base_agent.py`

### ФАЗА 2: ПЕРЕДАЧА КОНТЕКСТА БЕЗОПАСНОСТИ
- WIT-токены передаются между агентами в цепочке вызовов.
- Каждый агент проверяет родительский WIT перед выполнением.
- Отслеживание `session_id` и `user_id` через весь workflow.
- Полная цепочка делегирования: `Research` → `Analysis` → `Execution`.
- *Реализовано в:* `graph/state.py`, `graph/nodes.py`, `agents/base_agent.py`

### ФАЗА 3: ПОЛИТИКИ БЕЗОПАСНОСТИ (НАИМЕНЬШИЕ ПРИВИЛЕГИИ)
- Ограничение делегирования: кто кому может передавать управление.
- Контроль доступа к инструментам (`allowed_tools`).
- Требование одобрения человека для критических действий (`Execution`).
- Политики хранятся в промптах и могут обновляться на лету.
- *Реализовано в:* `config/prompts.py`, `agents/base_agent.py`

### ФАЗА 4: АУДИТ И НАБЛЮДАЕМОСТЬ
- Полное логирование всех действий агентов.
- Каждая проверка политики фиксируется в аудите.
- Все LLM-вызовы отслеживаются с метриками (латенси, токены, стоимость).
- Интеграция с Langfuse для визуализации трейсов.
- Генерация JSON-отчётов об аудите (`audit_report.json`).
- *Реализовано в:* `config/wimse_audit.py`, `config/observability.py`

## 📧 Email-интеграция

Система поддерживает автоматическую обработку входящих писем:

| Шаг | Агент | Действие |
| :---: | :--- | :--- |
| **1** | `ReadEmailAgent` | Читает новые письма из почтового ящика (IMAP) |
| **2** | `ResearchAgent` | Анализирует запрос и собирает контекст |
| **3** | `AnalysisAgent` | Глубоко анализирует данные и выявляет паттерны |
| **4** | `ExecutionAgent` | Разрабатывает пошаговый план действий |
| **5** | `FinalizeNode` | Формирует итоговый ответ |
| **6** | `SendEmailAgent` | Отправляет ответ обратно (SMTP) |

### 🔐 Безопасность email-агентов
- Каждый email-агент имеет WIMSE-идентичность (WIT-токен).
- Все действия логируются в Langfuse с WIMSE-контекстом.
- Политики безопасности применяются ко всем агентам.
- Human-in-the-Loop для критических действий.
